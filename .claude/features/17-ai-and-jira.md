## Context

Most of the user's THMP work starts as a Jira ticket (`https://thbs.atlassian.net/browse/MP-43512`) and is re-typed into Axon by hand. This feature adds a small AI layer (Claude through a Supabase Edge Function; the key never reaches the browser) and a Jira integration:
- **Describe tasks in plain words** and get one or several drafted tasks to review.
- **Import a task from a Jira link**, and **generate a checklist** from the ticket's description and comments on demand. (Keeping imported tasks in sync with Jira is wanted but **deferred until it's planned properly**; see the end of this doc.)
- Later: AI weekly and quarterly reports, and a chat over the user's tasks.

Jira import itself is **deterministic mapping, not AI**: the Jira API returns structured fields that map straight onto Axon's. AI is used only where judgement is needed (drafting from free text, checklists, reports, chat), and every AI result is **reviewed before anything is saved**.

It is a single-user app, but signup is open and Edge Function secrets are project-wide, so **every function serves only the owner** (`AXON_OWNER_ID`).

### Decisions (2026-09-28)
- **Update, same day: Gemini free tier is the default provider** (the user: both the Anthropic and Google card payments failed). The `ai` function is **multi-provider**: a model registry (`models.js`) with a provider per model, a Claude adapter (`claude.js`, kept as is) and a Gemini adapter (`gemini.js`, raw `generateContent` with `responseJsonSchema`). Models: `gemini-3.8-flash` (default for every job) and `gemini-3.5-flash-lite` on Google's free tier (no card; per-minute and daily limits; Google may use free-tier prompts to improve its products), plus the three Claude models, **listed but disabled** until an `ANTHROPIC_API_KEY` exists. Secret: `GEMINI_API_KEY`.
- **Provider:** Anthropic direct (Claude API), not OpenRouter: one data path for work content, official SDK, no top-up fee. All model calls sit behind one Edge Function, so switching provider later is a local change.
- **Models:** chosen per job in Settings → AI & integrations, and per request where there's a picker. Allowed: `claude-sonnet-5` ($2 / $10 per MTok), `claude-opus-5-5` ($4 / $20), `claude-haiku-4-5` ($1 / $5). Suggested defaults: Sonnet 5 for task drafting, checklists, weekly reports and chat; Opus 5.5 for quarterly reports.
- **API key:** pay-as-you-go prepaid credits from platform.claude.com. The build ships with a **placeholder**: until a real key is set, the AI surfaces show "AI isn't set up yet" with the steps, and nothing else breaks.
- **Jira:** Jira Cloud at `https://thbs.atlassian.net`, basic auth with the user's email and an Atlassian API token (secret). There's **no checklist in Jira**: checklists are generated by AI from the description and comments, **only when the user asks**.
- **Sync: on hold** (the user, 2026-09-28): a "Sync Jira" button on the Tasks page is wanted, but it needs better planning first (what it overwrites, conflicts, tags, deleted issues). It is not part of Phases 1–6; see "Deferred: Jira sync".

### 1.1 Database
Migration `add_ai_settings_and_usage`:

```sql
alter table public.profiles
  add column ai_settings jsonb not null default '{}'::jsonb
    check (jsonb_typeof(ai_settings) = 'object');
-- shape: { "models": { "draft_tasks": "claude-sonnet-5", "checklist": ..., "report_weekly": ...,
--          "report_quarterly": ..., "chat": ... } }; missing keys fall back to the defaults.

create table public.ai_usage (
  id             uuid primary key default gen_random_uuid(),
  user_id        uuid not null default auth.uid() references auth.users(id) on delete cascade,
  job            text not null check (job in ('draft_tasks','checklist','report_weekly','report_quarterly','chat')),
  model          text not null check (char_length(model) <= 80),
  input_tokens   integer not null default 0 check (input_tokens >= 0),
  output_tokens  integer not null default 0 check (output_tokens >= 0),
  cache_read_tokens integer not null default 0 check (cache_read_tokens >= 0),
  cost_usd       numeric(10,6) not null default 0 check (cost_usd >= 0),
  created_at     timestamptz not null default now()
);
create index ai_usage_user_month_idx on public.ai_usage (user_id, created_at desc);
alter table public.ai_usage enable row level security;
create policy "ai_usage_owner_all" on public.ai_usage
  for all to authenticated
  using (user_id = (select auth.uid()))
  with check (user_id = (select auth.uid()));
```

- The Edge Function inserts `ai_usage` rows **with the caller's JWT** (RLS applies; no service-role key).
- Verify (rolled back): a non-object `ai_settings` is rejected; another user's `ai_usage` rows are invisible. Run advisors.

### 1.2 Edge Function (`supabase/functions/ai/`)
```
supabase/functions/
├── _shared/
│   ├── cors.js          # CORS headers for http://localhost:6420 and the deployed origin; OPTIONS preflight
│   ├── auth.js          # requireOwner(req): Supabase client with the caller's JWT → auth.getUser(); 403 unless user.id === AXON_OWNER_ID
│   ├── claude.js        # Anthropic client (npm:@anthropic-ai/sdk), MODELS allowlist + prices, costOf(usage, model), aiConfigured()
│   └── errors.js        # json(status, body); maps SDK errors (typed classes) to { error: { code, message } }
└── ai/
    ├── index.js         # Deno.serve: preflight → requireOwner → route body.action → json response
    └── draftTasks.js    # the draft_tasks prompt, JSON schema, call and response shaping
```

- **Secrets:** `ANTHROPIC_API_KEY` (placeholder `sk-ant-REPLACE_ME` until the user sets it), `AXON_OWNER_ID` (the user's auth id). `SUPABASE_URL` and `SUPABASE_ANON_KEY` are provided by the platform. A `supabase/functions/.env.example` lists them (placeholders only; no real values in the repo).
- **Actions** (`POST { action, ... }`):
  - `status` → `{ configured: boolean, models: [...] }`. `configured` is false when the key is missing or still the placeholder; nothing is called.
  - `draft_tasks` → input `{ text, model?, context }`, where `context` is `{ today, timezone, weekStartsOn, fiscal: { label, start, end }, spaceName, tags: string[], versions: string[], statuses, priorities }` (built by the client). Output `{ tasks: Draft[], model, usage, costUsd }`.
- **Model rule:** `model` must be in the allowlist, else 400; missing → the job default from `profiles.ai_settings`, else the built-in default (`claude-sonnet-5` for `draft_tasks`).
- **`draft_tasks` call:** a fixed system prompt (Axon's field meanings, "only use the given tags unless one is clearly needed; mark new tags", "resolve relative dates from `today` in `timezone`", "don't invent dates, versions or priorities that weren't implied", "split into separate tasks only when the text describes separate pieces of work"). Structured output with this JSON schema; low effort:
  ```
  { tasks: [ { title (1–300 chars), description_markdown, status (enum), priority (enum),
               tags: string[], new_tags: string[], version: string | null,
               start_date: 'yyyy-MM-dd' | null, due_date: 'yyyy-MM-dd' | null,
               checklist: string[] } ], maxItems 20 }
  ```
  `stop_reason` is checked (`refusal`, `max_tokens`) before parsing; failures return a readable error. Each call logs one `ai_usage` row.
- **Not configured:** every AI action other than `status` returns `409 { error: { code: 'ai_not_configured' } }`.

### 5.2 Edge Function (`ai`, action `report`)
- Input: `{ spaceIds, spaceId | null, period: { kind, start, end, label, fiscalYear?, fiscalQuarter? }, range: { from, to }, model?, reportId? }`. `range` is the period as UTC instants (the client computes it with `zonedDayRange` in the profile time zone). `reportId` regenerates an existing report (same period); otherwise a new one is created.
- **Facts** (`reportFacts.js`), read **in the function with the caller's JWT** (RLS applies, nothing leaves the user's rows), capped to about 60,000 characters:
  - Tasks **completed** in the range (`completed_at`): title, Jira key, versions, tags, priority, completion date, the first 300 characters of the description.
  - **Status changes** in the range (`task_activity`), per task: from → to, for "moved to In review" and similar.
  - **Still open at the end**: in progress, in review, blocked or on hold, created before the end: title, key, status, due date; overdue flagged.
  - **Created** in the range (count, plus titles if few).
  - **Journal entries** in the period (`notes.kind = 'journal'`): date and `content_text` (each up to 1,500 characters).
  - Todos done in the range (count).
- **Prompt** (`report.js`): write a work report in Markdown for the given period and audience "a manager or lead": `## Summary` (3–5 sentences), `## Highlights` (the most significant completed work), `## Completed` (grouped by area or portal tag, then version), `## In progress`, `## Blocked or carried over`, `## Next focus` (for a quarter: next quarter; for a week: next week). Structured output `{ title, markdown }`; `title` like "Q2 FY 2026–27 report: THMP".
- The function **inserts or updates the `reports` row itself** (with the caller's JWT), so a long generation survives the user leaving the page: `content` stays null and `content_text` holds the Markdown; the client converts it to Tiptap JSON the first time the report is opened (a report with `content` null and text present is "fresh from AI"). Avatars, names, timestamps and actions (copy, regenerate, cost) go in the companion `Message` component the Bubble docs point to; check it and the style (the project uses `radix-nova`; the link is the Base UI docs) when Phase 6 starts.
- A chat page (sidebar item "Ask") with a model picker (switching mid-chat is allowed; it re-reads the conversation at full price, since the cache is per model).
- Claude uses read-only tools run by the `ai` function with the caller's JWT (RLS applies): search tasks, get a task, period summary, journal for a range. It can propose tasks as Phase 1 draft cards; nothing is created without the user's click.
- Conversations stored (`ai_conversations`, `ai_messages`), prompt caching on the system prompt and tools.

## Deferred: Jira sync (needs its own planning)
- Wanted: a **Sync Jira** button on the Tasks page (and per task) that re-fetches Jira-linked tasks and updates them.
- Questions for that plan: which fields Jira may overwrite and when (a three-way rule against a stored snapshot was proposed), how conflicts show, Jira labels vs tags the user added, issues deleted or moved in Jira, bulk search (`POST /rest/api/3/search/jql`), and whether sync logs to the task's activity.
- It gets its own phase (or feature) once planned; Phase 2 stores only `jira_key` and `jira_imported_at`.

## Data Model Summary (after Phases 1–3)

```
profiles ── ai_settings (jsonb: models per job)
         └─ jira_settings (jsonb: site, startDateField, statusMap, priorityMap)
ai_usage (n per user)            one row per model call: job, model, tokens, cost
tasks ── jira_key (unique per user while live), jira_imported_at
      └─ task_links              the Jira URL, labelled with the key
Secrets (Edge Functions): ANTHROPIC_API_KEY, AXON_OWNER_ID, JIRA_EMAIL, JIRA_API_TOKEN
```

### `ai_usage`
| Column | Type | Notes |
|---|---|---|
| `job` | text | draft_tasks, checklist, report_weekly, report_quarterly, chat |
| `model` | text | the model id actually used |
| `input_tokens`, `output_tokens`, `cache_read_tokens` | integer | from the API's usage |
| `cost_usd` | numeric(10,6) | computed in the function from the allowlist prices |

### `tasks` (Jira columns)
| Column | Type | Notes |
|---|---|---|
| `jira_key` | text | `MP-43512`; unique per user among live tasks |
| `jira_imported_at` | timestamptz | when the task was created from Jira |

## Out of Scope (All Phases)
- Writing back to Jira (status changes, comments): read-only integration for now.
- Jira sync of any kind (on demand or background): deferred until planned; see "Deferred: Jira sync".
- GitLab correlation of tasks and MRs: backlog (the user's idea, "not anytime soon").
- OpenRouter or other providers: decided against for now; the single Edge Function keeps it swappable.
- Semantic search with embeddings: Phase 6 starts with keyword and structured tools.
